### 20 分钟扩展流程

在上述流程基础上延长：

1. **2 分钟：数据流**——病例/MRI 文件、分析运行、分割工件、报告的版本关联；指向 API/SQLite/runtime 架构图。
2. **3 分钟：空间约束**——说明四序列必须来自同一患者并通过序列角色、方向、affine、spacing、覆盖和配准检查；系统不会以简单 resize 代替配准。
3. **3 分钟：模型边界**——介绍集成预训练 MONAI BraTS SegResNet；展示报告的模型修订、权重摘要、掩膜摘要与三种体积；说明单样本工程验证不等同精度评估或临床有效性。
4. **2 分钟：PACS 闭环设计与门控**——说明隔离 Stage7 Orthanc、受控后端 QIDO/WADO 代理和 Cornerstone；真实 UPENN 像素已在独立测试服务实际阅片，但该路径不用于固定 WAW 推理演示，正式 PACS 门控仍关闭。
5. **2 分钟：研究路线**——区分当前可复现核心工作流与尚待研究验证的影像组学/预测、LLM、RAG、多模态计划。

## 现场异常时的处理

- **前端不可访问**：先执行 `docker compose ... ps`；若容器已停止，仅启动隔离 RC：`docker compose -f E:\BrainFusion-AI\docker-compose.rc.yml up -d`，等待 backend healthy 后刷新页面。
- **病例页打不开**：直接用 `/case/1`；若 API 返回 404 或病例缺失，不创建伪造结果，也不重新推理来掩盖问题。可改为讲解已归档的真实报告截图/文本记录，但要说明不是现场页面验证，并记录该次演示失败。
- **工作站或序列加载失败**：刷新后重试一次；如果仍失败，使用报告页展示持久化输出，并现场说明阅片部分本次未通过。不切换到未经验证病例。
- **PACS 显示无法连接**：这是本 RC 的预期安全状态。说明真实 DICOM 链路仍待人工影像审核和认证联调，不要改配置或打开像素/导入开关。
- **报告不显示结果**：不要再次执行可能写入状态的分析。检查病例 1 的分析历史与后端日志；如没有成功版本，应停止结果演示并报告故障。
- **操作边界**：演示只切换序列、视图和掩膜显示。不要点“重新 AI 分析”“确认当前分割结果”“保存医生意见”或写入测量/标注按钮；这些会改变病例状态或数据。

## 当前一体化隔离研究演示（2026-10-26）

启动器从已验收的 `brainfusion-rc-20261021` 工程样本制作独立数据库和上传副本，默认保存在 `E:\BrainFusion-Runtime\research-edition\demo\unified-research-demo`。它不会修改原 RC 样本，也不会连接正式端口 `18100/18180`。首次启动大约需要复制 21 MB 的既有演示文件。后续启动会校验副本完整性；已存在且完整的副本会复用，数据库只做 SQLite 完整性检查，不重置数据。

在 Windows PowerShell 仓库根目录启动：

```powershell
.\scripts\start-unified-research-demo.ps1
```

脚本使用已有 `runtime311-cpu-delivery-20261017T1516_s4` Python 环境、仓库现有 `frontend/node_modules`、可用的本机 Node，以及 Runtime 中已核验 SHA-256 的两个研究模型。前后端使用动态分配的 loopback 端口（前端 5190–5249，后端 18231–18279）；地址及一次性本地演示登录密码会在启动控制台显示。账户只写入演示 runtime 的本地配置，密码仅保存 PBKDF2 哈希。浏览器使用 `http://127.0.0.1:<显示的前端端口>`。

正常退出：在启动 PowerShell 窗口按 `Ctrl+C`。启动器只停止它自己启动的前后端进程。隔离数据库副本、演示影像副本、账户哈希和日志会保留，供后续复用和检查；不会自动清理。

### 启动器边界与排错

- 启动前会核验临床模型、融合模型及各自 manifest 的版本和 SHA-256；任何不一致会在启动服务前停止。
- 生存 API 只允许 `SYNTHETIC_TEST` 请求，要求现有本地 doctor 角色会话和 CSRF 校验；该本地角色不是专业资质认证。
- PACS/DICOM 配置被指向隔离目录中的未配置路径；DICOM 转换与导入状态不会写入正式路径。SegResNet 推理权重在此模式下不配置，以避免意外重跑。
- 前端依赖、Python 运行环境或权重 manifest 缺失时，启动器报告具体缺失并停止，不安装或升级依赖。
- 启动失败的日志保存在演示根目录 `logs`。检查后端/前端日志和 `demo-copy-manifest.json`；不要删除演示根目录来重置，若需重新初始化应先检查保留数据。
- 运行时模型工件仍保留在受保护的 Runtime 路径，不复制到仓库或演示目录。
