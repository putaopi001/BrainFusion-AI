更新：2026-10-21。适用候选：`BF-RC-20261021.1`，仅限本机隔离科研演示。页面顶部标有“教学原型 · 非临床诊断”。演示不包含 UPENN 导入、真实 DICOM 像素或 UPENN 推理。

## 演示环境与准备

- Web：<http://127.0.0.1:18184>
- API：<http://127.0.0.1:18104>
- 已验证病例：病例 `1`，名称 `RC-Engineering-Smoke`，说明 `isolated release candidate inference validation`。
- 输入：既有 WAW-GliomAI 四序列 NIfTI 工程样本。数据集许可及其工程用途记录见项目数据文档；这是一个演示样本，不是临床队列结果。
- 已持久化输出：SegResNet 分析版本 `f01f37f194ae4290ba51cb53e9aeebab`，WT `6.284 mL`、TC `3.374 mL`、ET `0.008 mL`；报告绑定同一分析版本。报告显示医生复核“待复核”。
- RC PACS 配置指向不可用的隔离端点，用来维持关闭状态；面板提示无法连接属于预期，不应尝试导入真实影像。

开讲前执行健康检查：

```powershell
docker compose -f E:\BrainFusion-AI\docker-compose.rc.yml ps
Invoke-RestMethod http://127.0.0.1:18104/
Invoke-WebRequest http://127.0.0.1:18184/ -UseBasicParsing | Select-Object StatusCode
```

两个 RC 容器应为 healthy，API 返回服务信息，前端为 HTTP 200。不要为了演示启动正式 `brainfusion-backend` / `brainfusion-frontend`。

### 20 分钟扩展流程

在上述流程基础上延长：

1. **2 分钟：数据流**——病例/MRI 文件、分析运行、分割工件、报告的版本关联；指向 API/SQLite/runtime 架构图。
2. **3 分钟：空间约束**——说明四序列必须来自同一患者并通过序列角色、方向、affine、spacing、覆盖和配准检查；系统不会以简单 resize 代替配准。
3. **3 分钟：模型边界**——介绍集成预训练 MONAI BraTS SegResNet；展示报告的模型修订、权重摘要、掩膜摘要与三种体积；说明单样本工程验证不等同精度评估或临床有效性。
4. **2 分钟：PACS 闭环设计与门控**——说明 Orthanc 是独立归档、DICOMweb 提供查询/影像传输、Cornerstone 负责前端渲染；本次只展示 fail-closed 面板，不导入 UPENN。
5. **2 分钟：研究路线**——区分当前可复现核心工作流与尚待研究验证的影像组学/预测、LLM、RAG、多模态计划。

## 现场异常时的处理

- **前端不可访问**：先执行 `docker compose ... ps`；若容器已停止，仅启动隔离 RC：`docker compose -f E:\BrainFusion-AI\docker-compose.rc.yml up -d`，等待 backend healthy 后刷新页面。
- **病例页打不开**：直接用 `/case/1`；若 API 返回 404 或病例缺失，不创建伪造结果，也不重新推理来掩盖问题。可改为讲解已归档的真实报告截图/文本记录，但要说明不是现场页面验证，并记录该次演示失败。
- **工作站或序列加载失败**：刷新后重试一次；如果仍失败，使用报告页展示持久化输出，并现场说明阅片部分本次未通过。不切换到未经验证病例。
- **PACS 显示无法连接**：这是本 RC 的预期安全状态。说明真实 DICOM 链路仍待人工影像审核和认证联调，不要改配置或打开像素/导入开关。
- **报告不显示结果**：不要再次执行可能写入状态的分析。检查病例 1 的分析历史与后端日志；如没有成功版本，应停止结果演示并报告故障。
- **操作边界**：演示只切换序列、视图和掩膜显示。不要点“重新 AI 分析”“确认当前分割结果”“保存医生意见”或写入测量/标注按钮；这些会改变病例状态或数据。
