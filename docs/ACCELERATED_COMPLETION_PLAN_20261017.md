# 系统收尾提效执行计划

更新：2026-10-17。目标是尽快完成原批准系统范围，随后实际带教、独立预演、导师正式展示。不是增加功能或通过取消部署/真实数据验收缩短工期。当前事实快照见PROGRESS_REVIEW_20261017.md，变化以实际运行和最新交接为准。

## 1. 工期的关键路径

当前主要瓶颈不是缺少模型或前端框架，而是转换工具、登记、审核、激活和现有分析器尚未形成完整的用户操作链，以及真实四序列输入不足。现有真实NIfTI分析链、PACS阅片链、角色审核/激活、显式登记和同机CPU重建均应复用。

最近存在同日下午多次源码打包、分散核对及状态更新。它们并非没有价值，但不应继续每补一个子项就打一次完整包。改为按可操作功能批次实施、集成、验证；正常版本加载无需重复请求批准。

## 2. 唯一优先工作队列

| 顺序 | 交付结果 | 验收与停点 | 规划有效工时 |
|---|---|---|---|
| M1 | 用户可发起和续看的转换作业 | 复用convert_and_verify和显式登记；持久状态/失败原因、串行去重、刷新、重试及重启中断恢复；现有PacsPanel可操作，合法候选来源不足时说明具体缺项，不接受任意客户端本机路径；成功转换登记后才进入现有审核/激活，不自动推理 | 10–16h |
| M2 | 源码与活服务一致、分析来源绑定完整 | 隔离副本完成转换登记→审核→激活→现有分析入口的关联、旧结果失效与历史保留；必要几何/标签核对；备份和回滚后一次计划更新，实际API/浏览器确认版本与失败行为。仅无副作用批次才可不更新服务 | 6–10h |
| M3 | 匹配真实四序列的完整流程 | 合法来源/同一检查/明确角色/受支持共同空间，真实转换、审核、激活、模型、特征、叠加、复核、报告，验证代表失效/重启。没有数据就保持未验收，不以夹具或重封装NIfTI替代真实来源 | 6–10h，数据等待另计 |
| M4 | 当前版本联合恢复与最终交付 | 对本次新增内容做代表恢复：配置、转换索引及其外部产物/来源材料、业务关系、账户与归档；模型只读引用/分角色交付；最终全套和实际浏览器验收，冻结当前包、操作/恢复说明和真实截图 | 8–12h |
| E5 | 原范围容器/目标环境 | 等待权限期间可先完成Compose、CPU后端与受支持Linux特征工作器、PACS/账户及持久化配方；正常环境就绪后实际构建、CPU执行、重建恢复，不把Windows轮子或静态配置当Linux通过 | 8–16h，系统权限/安装等待另计 |

这些是余量规划，不是已完成工时或保证。M2/M4部分检查可共享，E5部分准备可在M3受阻时交错；不能将各范围机械相加或以小时触发次数折算产出。两次有效开发窗口后按实际完成行为、失败和外部前置重新估算。

## 2026-10-18 M4转换材料恢复范围已补齐，真实材料恢复未验

联合备份/恢复现在收录方案草稿、被网页捕获的原始DICOM、持久作业及转换输出，并在独立恢复目录内重写路径和更新源清单SHA；无法随包带齐的作业原始文件会阻止快照成功。16项隔离恢复测试通过。当前转换账本为空，没有实际材料供恢复或交付，也没有制作空的全系统备份。M4仍需等真实四序列产生材料后执行完整联合备份、独立目录恢复及链接核验，估算未因此宣告完成。

## 2026-10-18 M1新增页面入口已实现，真实数据验收未完成

PacsPanel可以选择已绑定同一检查中的四个不同序列，服务端重读受限元数据预览并检查原始空间；医生明确创建后，服务端重新确认归档关联/元数据版本、读取并核验归档原始字节，保存不可由浏览器指定的来源清单并创建queued作业。再由医生点击“启动转换”。新入口采用CSRF与病例绑定，不向浏览器暴露运行目录；原文件捕获失败时清理这次临时副本。该功能的合成集成验证和在线路由加载均已通过。

实际PACS仍为1检查/1序列，因此此项工程实现不等于真实四序列作业验收，M1仍保留在进行中。M2–M4、E5和带教/导师预演照原顺序推进；真实数据等待时继续恢复材料与交付说明，不用模拟夹具声称临床闭环。证据详见`PROGRESS_REVIEW_20261018.md`和本次`NIGHTLY_HANDOFF.md`。

## 3. 真实数据条件单独尽早解除

- 下一有效窗口先做一次有限核实：已有授权本地资料与来源清单是否存在同一检查的T1n/T1c/T2w/FLAIR、许可/来源记录与支持几何。数据审计默认预算2–4有效小时；它是策略切换点，不能到了时间自动放行或删掉任务。
- 若本地不足，继续由Codex在既有公开数据授权内做有限官方候选发现与元数据核验，先确认四序列/几何及许可，再考虑小样本下载；不下载全队列、不重新加入E:/archive，不把文件名当最终角色依据。需要最新外部来源时按实际访问核查。
- 候选不合格应记录具体缺项和一个可执行下一步，条件不变不反复连接旧失败地址。用户只处理确需本人提供的账号/许可、系统授权和影像抽查；不把全部公开数据检索推回用户。
- 普通DICOM阅片和工程转换验证不要求IDH标签；真实四序列工程样本不等于独立研究评价队列。标签极性和预训练重叠仍限制对应研究解释。
- 在外部资料等待时转M1/M2、E5代码准备或M4新增恢复实现，不能停工，也不能靠反复源码审计冒充功能推进。

## 4. 夜间执行方式

1. 一条串行开发线，沿同一里程碑续做，不在每个小时从头理解全项目。先读最新交接和本计划；相关历史按需读取。保持现有互斥包装器，常驻服务/只读监测不占开发锁。
2. 每批对应一项可观察的新行为或实际缺陷修复，尽量同时接后端、现有页面和相关验证。测试组件可先用隔离夹具，但真实验收单列。不得为了让页面出现按钮而增加空接口，也不为无变化代码增加重复测试。
3. 默认只跑变更相关检查；共享模型/任务/数据生命周期的跨模块改动或候选集成后做整体回归，最终冻结再确认。新失败或之后修改使证据失效时必须补验，不为省额度跳过必要检查。
4. 一组相关变更完成后集中部署验证。每晚通常保留一个集成候选；出现需要回滚、独立环境验证或重大故障时可以额外生成。日常保留源码差异和证据即可，不因每次子改动重复完整ZIP、复制650文件或重做192实例导入。
5. 不等跨夜监测结束再开发；有期限观察可与开发交错。计划停止和异常退出分开记录，观察不能替代新版本验证。
6. 文档按实际需要更新：简短当前交接、发生变化的台账、必要操作说明；保留历史但不每批把同一段复制进多份路线图。仅文档/打包子项不得报告为产品功能完成。当前状态不要混入未标明的旧标题。
7. 阻塞条件不变时安静续做独立任务；没有可独立实施项则报告真实缺项后结束，不用研究扩展、重复预检或新任务凑满8小时。

## 5. 白天抽查与论文材料

每天最多提供三项可直接操作的检查，给出入口、步骤、预期结果和本次改变。优先验证转换作业刷新/失败、审核激活后的当前输入、旧报告失效或恢复等当晚实际改动；用户反馈若影响主流程，次夜先修。

论文材料随稳定模块收集：功能/架构/数据库、来源/任务/版本设计、测试与失败、性能边界、真实截图。完整正文仍需学校模板与导师要求，不能把现有材料视为论文完成。不要在系统关键路径未完成时新增融合、校准、模型或研究终点；已批准研究余项保留，SCI不是系统交付前置，也不能称已完成。

版本冻结后执行六次约1–2小时实际带教和两次独立演示预演，学习以用户掌握程度调整，不能为了赶日程跳过。

## 6. 时间判断

系统收尾暂仍按约2–4周，带教/预演约1周；数据和环境前置及时就绪、每晚产生可验收进展时，争取靠近下限。当前没有事实依据保证几天全部完成。M1/M2两个有效窗口之后用实际产出修订预测，不因提示词变长或任务触发八次而直接压缩承诺。
