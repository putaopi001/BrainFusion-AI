# 数据集与标签计划

## 首要门槛

先选择一个主数据体系和一个明确预测终点，再扩展数据。分割标签并不等于临床风险、IDH、MGMT 或生存标签；不同数据集具有不同任务，不能按文件名或近似年龄随意拼接患者。

分割与预测可以使用不同队列，但多模态预测的各分支必须在同一队列按可靠患者标识匹配。匹配不到的模态不能用其他患者代替。

## 注册表与存储

建议结构（大型数据位于仓库外）：

```text
data_root/
  raw/                 # 原始数据只读
  derived/             # 版本化变换、mask、特征
  registry/            # 数据来源与元数据
  splits/              # 患者级清单及哈希
  centers/             # 虚拟/真实来源中心映射
```

registry 至少记录 dataset_id/version、来源/许可、下载日期、患者/检查伪标识、序列路径、shape/affine/spacing、原始标签映射、临床字段和终点定义、纳排原因、中心来源、校验哈希与重复检查结果。公开仓库只存脱敏模板及可公开协议。

## 数据就绪流程

1. 核对序列及标签；抽查 2–5 个病例贯通读取、方向、分割与显示。
2. 检查跨年份/数据来源的患者重叠；同一患者所有扫描和时间点归同一集合。
3. 默认候选为患者级 70/15/15 train/validation/test，比例需依据标签频数调整后冻结。样本不足时在开发集做交叉验证并保留独立测试；不强行承诺足够统计效能。
4. 仅训练集合拟合插补、标准化和特征选择；验证集选超参数、校准与融合规则；测试集封存至最终方案锁定。
5. 核验 checkpoint 的训练病例是否与评估集重叠。来源不明时披露，不能称“独立外部验证”。
6. 官方 validation/test 隐藏标签时使用官方允许的评估通道，或从公开有标签开发数据留出；明确数据角色。

## 多序列与空间契约

序列身份来自数据元信息与模型配置，不默认编号固定。模型需要多序列时检查同一检查、配准、shape、affine、spacing；模型空间预测逆变换回原空间。mask 必须验证几何与标签，不仅 shape。

## 虚拟中心

只从训练集合分配 3–4 个中心，validation 按统一预注册规则使用；test 不进入任何中心训练或聚合评分。

- IID：患者分层随机分配，记录种子。
- Non-IID：优先用真实来源/扫描仪信息；没有信息时用预定义标签偏斜（候选 Dirichlet alpha=0.5、0.1）和数量偏斜，显式标为模拟。
- 最小中心样本及各类别数量需检查；单类别中心 AUC 不可计算时使用预定义排除/替代规则，不能填 1。
- 所有方法复用完全相同划分；不把虚拟中心称作真实医院验证。

## 数据不足时

临床或预测标签不足：交付真实分割及真实 mask 特征，并将多模态/联邦分类降级为延期研究项。若只保留工程模拟，其结果单独列出，不纳入医学性能报告。生存任务仅在有时间、事件与删失字段时启动。
