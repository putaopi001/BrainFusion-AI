# Codex 项目实施规则

范围：BrainFusion AI 年底科研工程计划。此文件是项目约定文档，不自动替代当前会话授权或 AGENTS.md。

## 开始工作

阅读 CURRENT_STAGE、MASTER_ROADMAP_2026 和涉及任务的协议；查看 git status，保护用户现有改动。当前工作树与 E:/BrainFusion-AI 是同仓库不同工作目录，不在两个目录同时编辑实现。默认在当前工作树实施，合并后主目录再同步。

## 允许的实施工作

当前任务范围内的代码修复、脚本、测试、配置、文档和本地可逆验证。训练脚本可以准备；实际长时训练应先核实资源、数据权限与实验配置，云费用、发布和外部写入按用户授权处理。不要仅因本文件重新询问已授权动作。

## 必须遵守

- 真实模型缺失时显式失败或显示 unavailable；mock 只能用于明确的演示模式。
- 不制造标签、性能、论文引用或通过记录，不把接口存在标为能力完成。
- 统一方向/空间契约；预处理随模型配置，不将通用归一化强加给所有 checkpoint。
- 输出记录输入 MRI/序列、模型版本/哈希、配置、时间和运行状态；医生确认绑定结果版本。
- 标准化、插补、特征选择、校准、TOPSIS 参数只在允许的训练/验证数据拟合。
- 模型、患者数据、密钥、大型产物不提交仓库。未核验的环境目录不移动或删除。
- 小批次修改，运行与风险匹配的检查；测试失败先修复或报告，不能写“全部通过”。
- 导师路线包括 PACS 基座、机器学习预测与大模型报告；当前先完成现有工作，大模型暂缓至结构化报告稳定后另行评估。未明确纳入的 K8s、第二套 UI 等不扩展。实验结论与报告功能不得超出证据。
- 修改架构需解释目的和迁移影响，更新文档；不为了减少代码量破坏历史数据。

## 交付记录

每批记录：改变的行为、验收命令与结果、证据路径、未验证内容、下一步。实验失败记录 OOM、数据异常、checkpoint 不兼容等真实原因；训练恢复需记录新的配置与 run_id，不能把不同配置结果拼成同一次运行。

## 分工

Codex：实现、重构、数据转换、可复现配置、指标脚本、适当测试与文档。

项目负责人：数据使用权限、标签语义、影像抽查、终点选择、算力安排、研究结果解释及导师沟通。

本计划不要求持续自主运行到年底，也不创建自动化或子代理。每次工作以当前明确任务与授权为边界。
