## 3. 当前演示：启动、打开、检查与关闭

当前正式演示是隔离的只读 Docker Compose 环境。它用于查看病例17既有NIfTI结果，以及病例19的PACS检查/序列/空间元数据；不能上传、修改、导入或重新推理。Orthanc由你在外部PowerShell前台运行，演示时保持该窗口打开。

### 启动当前演示

1. 确认 Docker Desktop 已启动，左下角显示 Engine running。不要同时启动第二套同端口项目。
2. 打开普通 PowerShell，逐行执行以下命令（这是启动只读演示，不会开启MRI上传或模型推理）：

```powershell
$project = 'E:\BrainFusion-AI'

docker compose --env-file $envFile --project-directory $project -f (Join-Path $project 'docker-compose.yml') up -d --no-build
```

3. 等容器启动后，在浏览器打开 `http://127.0.0.1:18180`。后端 API 地址为 `http://127.0.0.1:18100`，一般操作不需要直接打开API。

## 6. 运行真实分析

以下“运行分割模型”仅适用于已配置权重且允许写入的隔离NIfTI开发副本；当前18180演示禁用新上传和推理。数据条件满足后，在“AI 分析”页面确认四序列上传状态正常，点击“运行分割模型”，页面自动轮询状态：

| 状态 | 含义 | 操作 |
|---|---|---|
| 未启动 | 当前输入尚未提交 | 上传完整四序列后启动 |
| 排队中 | 等待串行 worker | 等待，不重复提交 |
| 分析中 | 正在执行真实模型 | 保持服务运行 |
| 完成 | 掩膜、体积和报告已保存 | 进入病例阅片 |
| 失败 | 本次未生成有效成功结果 | 阅读错误、查看日志，修复后重试 |

本系统的该按钮运行固定的MONAI BraTS SegResNet四序列分割模型，不是IDH分类器。权重位于主机 `E:\BrainFusion-Runtime\models\monai-brats\models\model.pt`（Compose内 `/models/models/model.pt`，只读）。成功页面显示模型、分析ID和体积；输出掩膜及任务记录写入该可写副本的 `uploads/case_<系统病例ID>/<分析任务ID>/`。重复提交返回409时页面续接已有活动任务；刷新页面保持该版本。状态请求失败会隐藏旧成功内容、禁用未知状态提交，点击“刷新任务”恢复；失败后可“重试分割模型”，生成新版本。没有无法测量的百分比进度。滑窗计时不是整个请求耗时。
分析历史位于分析任务卡下方，展示当前/历史版本、状态和创建时间；历史成功版本只显示元数据，不在此页重现旧结果或提供它作为当前阅片/报告输入。当前状态接口失败时，历史接口仍独立加载，页面分别显示状态错误和历史读取告警；病例切换会清空旧列表并丢弃迟到的旧病例响应。

分割成功页面可进入同病例研究页。输入默认来自关联患者；需要调整时保存病例独立研究版本，再提取自动掩膜特征。该研究页的IDH概率是独立研究原型输出，不是上面的MONAI分割预测，也不是诊断结论。MRI/mask文件变化、临床或模型版本过期时旧概率不显示，历史保留。结果仍是参考模型输入迁移实验，独立于医生意见/诊断报告；见AUTOMATIC_FEATURE_OPERATION_GUIDE.md。

## 7. 阅片与标注

点击“阅片与医生复核”或“阅片”。轴位/冠状位/矢状位默认FLAIR；“当前序列”可切换T1c/T1n/T2w/FLAIR，各视口显示身份。切换保持物理网格上的位置/方向/叠加与标注，每序列记忆窗宽窗位。只接受已有同患者、已配准、shape/affine一致、正交1mm数据，不自动配准或重采样；旧单文件标明序列未标识。

点击“AI分割叠加”查看预测区域：蓝色为核心中的非增强部分，黄色为 FLAIR 异常区，红色为增强区。查看来源提示，上传参考掩膜与真实模型结果有不同说明。按钮不可用通常表示当前没有有效掩膜。

## 8. 医生意见与版本确认

在病例详情填写医生意见并点击“保存医生意见”。检查原始影像及分割后，点击“确认 AI 结果”。确认只能绑定当前成功分析 ID，旧版本或未完成结果不能确认。

重新分析会立即撤销旧确认并隐藏旧报告，成功后形成新版本；需要重新阅片和确认。确认仅记录医生复核流程，不证明分割准确，也不会对掩膜边界进行自动修正。

## 9. 查看报告与导出 PDF

从病例列表点击“报告”，检查患者/病例信息、模型 revision、分析 ID、WT/TC/ET 体积、医生复核状态和意见。

WT 是全肿瘤区域；TC 是肿瘤核心；ET 是增强区域。三者有包含关系，不能将三个体积相加当作总肿瘤体积。未接入的风险模型显示尚未提供。

点击“导出 PDF”，浏览器生成下载文件。导出按钮只在当前有有效模型报告时启用。为避免浏览器默认下载到 C 盘，在浏览器设置中开启“每次下载前询问保存位置”，将 PDF 保存到 E:/BrainFusion-Runtime/results/exports。旧 PDF 是导出时的快照，重新分析后必须重新导出并检查分析 ID。

## 10. 常见问题

| 现象 | 排查与处理 |
|---|---|
| 页面打不开 | 检查启动日志、端口和后台进程；确认前端/后端都启动 |
| 端口已被占用 | 已是本服务则直接访问；否则换两个端口并用启动脚本统一设置 |
| 422 缺序列 | 使用“AI 分析”的四序列表单，不使用单文件入口代替 |
| 422 几何不一致/不支持间距 | 使用已下载配准样本；外部数据先完成配准与重采样 |
| 503 权重不可用 | 检查 MODEL_DIR 和 models/model.pt；本机官方权重已存 E 盘 |
| 409 活动任务 | 等待当前任务结束后再上传或重试 |
| 409 旧版本确认 | 刷新详情并确认当前成功分析 |
| 掩膜或报告消失 | 新上传/重新分析使旧结果失效，等待当前任务成功 |
| 服务重启后任务失败 | 查看中断记录，重新提交；已有成功结果保留 |
| 错误掩膜上传被拒绝 | 核对 shape、affine、标签 0–4；拒绝时原有效结果保留 |
| TC/ET Dice=0、HD95=null | 可能一侧区域为空，检查 empty_rule 和原掩膜，不把 null 当 0 mm |
| PDF 保存到 C 盘 | 浏览器下载设置改为询问位置并选择 E 盘 |

当前Compose服务日志可在PowerShell查看：`docker logs brainfusion-backend`、`docker logs brainfusion-frontend`。单次分析的 `worker.log`、`request.json`、`result.json` 位于该可写运行副本 `UPLOAD_DIR/case_<系统病例ID>/<分析任务ID>/`；当前隔离Compose主机映射是runtime/uploads。若使用原生开发环境，应以其启动登记中的 `UPLOAD_DIR` 为准，不要照搬旧的 backend/uploads 路径。

## 11. 显存、测试与后续范围

当前模型单进程串行滑窗，batch=1，输入与输出拼接留在 CPU，GPU 预算 6000 MB。空闲显存不足 3 GB 时走 CPU；CUDA OOM 会单次 CPU 重试并记录原因。五例原验收的 PyTorch 峰值分配约 505 MB，不等于显卡总占用。可用 nvidia-smi 查看当前全卡占用；不要同时运行其他训练。

日常查看已保存结果无需重新推理。pytest 和构建方法见 LOCAL_RUN.md。verify_core_workflow.py 会实际上传、推理并追加工程病例；verify_core_browser.mjs 会改动工程确认/标注并导出 PDF，只有需要重新验收时才运行，且应使用专用工程数据库。不要启动多个共享数据库的服务来执行推理。

IDH 分类、平均/固定/TOPSIS 融合、三轮同构模拟联邦已完成 CPU 原型。参考掩膜表格使用发布特征；新增自动掩膜卡使用当前病例预测掩膜真实提取特征。两者使用同一个参考掩膜训练的模型，研究概率未进入病例报告。操作见 RESEARCH_OPERATION_GUIDE.md、AUTOMATIC_FEATURE_OPERATION_GUIDE.md，指标和限制见 STAGE_4/6_VALIDATION.md。

E4本机隔离CPU工作器已有验收。E5的Docker Desktop/Linux Compose工程运行已通过：前后端隔离容器健康、PACS元数据连通、只读挂载拒写及重建后持久化均有记录；当前只读演示端口为18180/18100。该验收不代表干净机器安装，也不代表真实四序列DICOM到AI。烧录隐私、来源许可、序列角色和共同空间仍待获准人员确认；因此PACS像素读取、导入及AI桥保持关闭。研究队列、IDH标签语义和独立效能评价仍有限制；详见RELEASE_SCOPE、E5_DOCKER_RUNTIME_VALIDATION_20261020.md与SYSTEM_COMPLETION_CHECKLIST。

### 分割评价软件演示（仅隔离合成测试）
