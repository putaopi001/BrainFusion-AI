## 定时任务中保存的入口提示词

在 E:/BrainFusion-AI 本地项目中接续 BrainFusion AI。每轮先读取 docs/DAILY_SYSTEM_COMPLETION_TASK.md 的当前版本，再读 docs/REMAINING_WORK_PLAN_20261016.md、docs/SYSTEM_COMPLETION_CHECKLIST.md、docs/NIGHTLY_HANDOFF.md 头部和 docs/REVIEW_FEEDBACK.md。按最新用户指示与现行规程，优先解决运行稳定性、实际缺陷、真实DICOM到AI桥接和交付。实际写入/测试/启停使用 backend/tools/run_development_step.ps1 执行有限同步步骤，保护现有改动和正式数据。每轮完成一个有验收标准的小批次，保存可核对证据并给出下一步；不重复历史已验任务，不因阻塞而扩大离线实验。仅当有新增进展、失败或必要用户动作时给出实质通知；条件不变的阻塞简短记录。不要更改现有任务的频率或创建其他定时任务。

将以上一段保存进现有定时任务即可。以下正文留在项目中供每轮读取，避免保存的长提示词长期引用旧状态。本次文件更新不代表应用中保存的提示词或定时配置已经更新；本会话没有可用的定时管理工具，不直接修改应用私有配置。

## 1. 当前基线与目标

技术基线：Vue3/Vite/Pinia、Cornerstone3D 5.7、FastAPI/SQLAlchemy/SQLite、Orthanc 1.13+DICOMweb 1.24、MONAI SegResNet固定分割器、独立CPU PyRadiomics工作器与表格研究模型。延续现有实现，不推倒重做或升级主CUDA环境。

截至2026-10-16：P1受支持NIfTI和P2受控真实DICOM已验收；17表完整联合恢复、本地复核账户、Edge两来源保存/恢复和来源PDF已有证据。旧“Cornerstone未接入”“Orthanc未下载”“17表联合恢复未做”均不再作为当前待办。P3真实四序列桥仍未完；本地转换/检查工具尚无可直接激活的产品入口，不只是缺数据。

最新服务恢复与病例导航修复见LOCAL_SERVICE_RECOVERY_VALIDATION，退出原因仍未定位。实际PID、启动时间、路径和健康每轮实时核对；只读监测进程和常驻服务不持开发锁，不因其存活跳过开发。后端健康为GET `/`，不是不存在的`/health`；账户为`/local-auth/session`；PACS `/pacs/status`还须核data.state/read_available，不能只看HTTP200。

优先序：当前用户反馈/数据与版本错误 → S0/S1稳定性与失败回归 → S2现有流程交互 → 具备前置的B1–B4真实DICOM桥及S3/S4可复建交付 → S5/S6最终验收及论文材料。优先补模型桥的实际功能缺口；真实数据受阻时可先做B1/B2组件与独立交付，不能把无数据等同于完全不能开发。任务编号、依赖和剩余工时见剩余工作计划；每完成一批据实际结果调整，不强行依编号空等。

目标完整闭环：受控DICOM/PACS或受支持四序列NIfTI → Cornerstone阅片 → 可追溯输入 → 真实分割/叠加 → 自动掩膜特征/研究预测 → 人工复核 → 当前版本报告/PDF → 保存、恢复与可复建部署。普通DICOM阅片不要求IDH标签/四序列；DICOM模型分析则必须满足独立角色/空间/来源门槛。两个分开的演示流程有价值，但不能据此宣布真实DICOM到AI全闭环完成。

## 2. 每轮开工：只读预检

1. 系统UTC转Asia/Shanghai记开始时间和唯一run_id。首次读本规程、剩余计划、当前台账和交接；以后只读这些文件的当前摘要/变动与相关实现，避免反复遍历历史。CODEX_RULES是项目约定，过时内容按用户授权与本规程解释。
2. 查看Git状态与目标文件SHA，保护现有修改/未跟踪实现；不reset、clean、覆盖或自动提交/推送。当前正式路径引用旧nightly目录，不能当临时文件清理。
3. 核实登记PID和精确启动时间、监听所有者、日志与实际健康；检查分割/特征/导入、下载、构建和退出监测是否仍运行。已有任务续接，已有服务按脚本复用，不重复创建。
4. 前一轮仅记录healthy不代表现在健康；重启成功也不证明退出根因解决。监测已到期/结束才决定是否需要一次新的有期限观察；观察期间继续可独立开发，不持锁等待数小时。
5. 确定本批一个具体结果、输入基线和验收方法。先修尚未解决的真实失败，再扩展功能；不为了“全面检查”每小时跑全套测试。

## 3. 单实例与实际执行

所有修改项目、测试、构建、依赖/数据写入、启停服务、业务库/配置切换通过同一个包装器执行。先在本轮Runtime证据目录准备有限PowerShell工作脚本，再调用：

```powershell
pwsh -NoProfile -File E:/BrainFusion-AI/backend/tools/run_development_step.ps1 -RunId <run_id.step> -ScriptPath <E盘本轮工作脚本.ps1>
```

- 工作脚本内重新检查目标基线后才写。多个依赖写入与“切测试副本→验收→回正式路径”在同一个同步步骤中，用try/finally回原配置、服务和数据目录。
- 包装器在执行真实步骤的同一进程持有FileShare.None，正常/异常完成即释放；退出73表示争用，不执行步骤、不替换对方元信息。禁止再运行退役hold_development_lock.ps1或建立owner/holder互相保活循环。
- 不删除锁文件来解锁，不按一小时阈值抢锁。JSON可陈旧，以实际句柄及身份/命令/子进程/日志为据；无法确认互斥就停止写入并报告一次具体诊断。
- 开发子进程必须同步等待，退出码保留，不能用最后成功输出掩盖失败。不能在包装器外编辑产品代码/测试库，或启动脱离锁的后台开发写入。纯只读检查、准备尚未执行的Runtime脚本无需空占锁。
- 常驻服务按既有start/stop/reuse脚本及独立PID登记管理，默认隐藏启动；不得误停用户进程。注册长时模型/下载任务需身份、配置、日志和可恢复输出，后续在锁内先核状态再使用产物，不重复GPU任务。

## 4. 近期系统任务的实施要求

S0/S1：读取本次全面审计的失败日志；定位真实失败是产品、测试隔离还是历史断言，修复原因，不能删除保护/降低断言制造全绿。保留服务退出日志和监测结果，区分正常停止、异常退出、监测中断；只有证据支持才写根因。完善必要的启动/停止/状态和错误提示，有限复现与跨夜观察，不能每轮重启后声称稳定。

S2：在隔离数据副本复验患者/病例选择、四序列上传、分割/特征任务状态与重试、切病例/刷新、研究输入版本、复核/报告。只修实际缺陷，复用现有页面；Cornerstone只声称已可靠开放的工具，原mask只读，不额外开放未验编辑。

S3/S4：先有当前修复的源码差异/清单检查点，再做最终候选。源码/依赖环境/模型/业务快照/账户与PACS私有配置/导入来源材料分角色交付；运行根和四项额外配置明确，不遗漏账户/回执。逐项核对“干净目录复建”和“已装环境复用”的区别；旧ZIP、Windows轮子和同机数据恢复不能自动算新机/Linux通过。仅影响交付组成或已定位问题时更新增量，不按小时重打全包或复制650文件。

B1/B2：四序列角色确认必须绑定Study/Series/实例、来源字节、审核身份与转换版本，不按文件名猜角色。实现检查/转换作业、可恢复状态、审核通过后原子激活当前输入及旧结果失效/历史保留；只有被实际审核的版本可供现有AI执行器使用。不能把现有只读检查中的False直接改True，也不能上传转换输出而丢失PACS来源链。原输入不覆盖，失败不改变当前成功输入，推理中输入切换须明确拒绝。

B3/B4：核对DICOM LPS与NIfTI affine/轴向/spacing及标签映射；模型掩膜叠加、物理测量、特征、复核与报告都绑定当前来源/输入/分析版本。无受支持共同网格时具体拒绝，不静默配准/重采样。合成夹具可先验证组件，匹配真实四序列样本取得后再验实际PACS到AI全流程、重复请求/刷新/重启/来源变动及恢复；真实数据门槛未过保持待验证。

E5：当前Compose缺完整PACS/账户配置及受支持Linux特征运行配方，环境就绪后还需开发和实测。仅在正常系统权限和合适重启窗口具备后配置Docker/WSL，优先CPU、只读模型、持久化与重建。不得重试/绕过先前被自动审批拒绝的Orthanc环境动作；用户人工提供并已正常运行的本机归档继续复用。

## 5. 研究与论文材料

系统可独立任务仍未完成时，R2校准/新消融等离线扩展居后；不要因P3受阻立刻无限添加研究子实验。R3完整轻量参考表格模拟已有验收，输入/方法不变不重训。完成可独立系统任务后，可按既有授权接R1/R2/R4，必须对应明确未完项及论文所需证据。

R1实际新增MRI仍0，152人是ZIP清单，五例只是工程数据；仅官方网络/可核对资料出现新证据时续冻结v2十训练人小批，不按小时重复DNS/TLS失败、不关闭TLS校验。完整训练侧自动/参考掩膜协议、分割/空区域/失败分母、特征与模型重拟合另验；不以10例代替完整队列或独立评价。

保持98/21/22角色，22已观察者为探索性，不重分冒充独立。拟合/插补/标准化/选择/校准只用允许训练/验证来源；不拿真实Dice/标签生成部署权重；种子、中心和重复方法行不当独立患者。保留熵权无优势、校准变差及失败；IDH0/1极性和预训练重叠未核清时不升级临床结论，新研究结果不未经门槛直接切产品模型/latest。

论文材料随已完成系统批次更新：设计需求、架构、数据库/来源谱系、阅片/模型/任务实现、测试/性能/恢复表、实际页面与局限。已有图与证据先复用，界面变更影响图才重截；不每轮重绘、写整篇论文或启动多代理论文流水线。完整毕业论文另按学校模板及导师要求组织，SCI不是本阶段停止条件。

## 6. 执行边界、验证与额度

- E盘放数据/模型/缓存/结果；先查已有环境和可信来源。保持主CUDA、固定分割器/选中特征协议；GPU batch=1，预算≤6000MB。新环境独立建立，不盲升级。
- 默认选变更相关的测试和真实路径验证；全套检查只在跨模块变更/最终候选/本次已知全套失败修复后执行一次。浏览器/API/真实模型/合成夹具的证据各自注明，不混称全通过。PDF变更需实际打开看排版。
- 同问题两次无进展换策略；外部条件不变记录一次阻塞和解除条件，转下一个可实施系统项。没有可独立任务时结束本轮并列清必要输入，不凑时长/增加文档审计或新接口。
- 保护正式17表、原影像/mask/模型和成功产物，写入验收使用副本。备份、恢复和停止进程前核绝对范围/身份；不清理未知nightly目录。不自动提交/推送/发布/付费/发消息给别人，不擅自重启电脑。
- 仍排除E:/archive四分类数据、Ki-67/CD40LG/生存、第二UI、LLM报告、自动配准、完整3D训练、医院现网PACS及DICOM SEG/SR回写。通用任意DICOM上传、完整医院RBAC、所有ROI/编辑工具不自动升级为本期必做范围。

## 7. 每轮交付与完成条件

每批留下实际行为、文件变更、测试命令/退出码/结果、必要日志、未完项和下一步。证据E:/BrainFusion-Runtime/results/nightly/YYYY-MM-DD/run_id，按北京时间，同名不覆盖；不输出患者正文/凭据/活Token。锁释放/临时路径回原和剩余进程状态必须真实可核对。

维护一个简短当前交接，不将整段历史重新抄入所有文档。台账只更新发生变化的任务；CURRENT_STAGE保留简短当前摘要，daily追加一次实际批次。每晚一次汇总剩余工作；条件不变的跳过不要反复长通知。

最终回复包括：本批交付；实际验证和证据；未解阻塞/必要用户动作；最多三项可操作的白天抽查；下一批第一步。小时触发不等于一小时有效开发，不凑满八小时、不保证无人值守全程成功。

本机候选、真实DICOM-AI全闭环、Docker/异机交付、研究完成分别验收。系统全部批准必做项通过才报告完整交付；真实四序列/授权/独立评价缺口保持明确，不用“延期”抹去。用户选择提前采用范围受限候选时写清范围，不能自行称全面完工。达到完成条件后结束开发并通知用户管理现有定时任务，不假称已关闭计划。
